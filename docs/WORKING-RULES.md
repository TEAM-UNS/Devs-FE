# UNS 작업 규칙

## 이 문서의 목적

UNS는 웹 프론트엔드 포트폴리오의 중심 프로젝트다. 목표는 동작하는 서비스가 아니라
**면접에서 설명할 수 있는 결과물**이다. 따라서 구현 속도보다 "이 부분을 내가 소유하고
있는가"가 우선한다.

읽으면 이해되는 코드와 직접 쓸 수 있는 코드는 다르다. 이 문서는 그 간격을 좁히기 위한
규칙이다.

## 층 구분

작업을 세 층으로 나눈다. 위임 여부는 층으로 결정한다.

1. **퍼블리싱 층** — 마크업, 스타일, 반응형, 컴포넌트 껍데기, 반복 UI
   → 전부 위임한다. 면접에서 묻지 않는다.
2. **로직 층** — 검증 스키마, 상태 설계, 에러 표시 시점, 데이터 흐름
   → 설계는 내가 하고 구현만 위임한다.
3. **결정 층** — 라이브러리 선택, 토큰 저장 위치, 라우트 가드, 서버 상태와 클라이언트
   상태의 경계, 최적화 대상 선정
   → **위임하지 않는다. 여기가 면접의 전부다.**

## 내가 직접 소유하는 항목

이번 방학 기준으로 아래 다섯 개는 스스로 작성한다. 파일 경로는
[CLAUDE.md](../CLAUDE.md)의 소유 항목 표에 있다.

- auth: Zod 검증 스키마
- auth: 전공 복수선택과 기술스택 드롭다운의 파생 상태
  (전공을 해제했을 때 이미 선택된 기술스택 처리 포함)
- auth: 토큰 저장 위치와 라우트 가드
- 대시보드: 측정 → 병목 진단 → 개선 → 재측정 전 과정
- 로드맵 기간 설정 UI (휠 및 버튼 입력)

이 목록 밖의 것은 마음 편히 위임한다. 목록에 없는 새 작업은 이 기준으로 판단한다:

> **어렵지만 값진 것은 내가 소유한다. 반복적이거나 값어치가 낮은 것은 위임한다.**

"어렵고 값지다"는 정답이 하나가 아니고 선택에 근거가 필요한 것, 즉 면접에서 물어볼 만한
것을 말한다. 애매하면 소유 쪽으로 기운다.

## 작업 루프

1. **화면 단위로 먼저 적는다.** 어떤 상태가 있는가, 검증은 언제 도는가, 에러는 어떻게
   뜨는가, 데이터는 어디서 오는가.
2. **적은 내용을 지시로 바꾼다.** "회원가입 페이지 만들어줘"가 아니라 "이 스키마로 이
   시점에 검증하고 이렇게 표시해줘". 지시가 안 써지면 그 부분은 아직 모르는 것이다.
   이 단계가 자동 필터 역할을 한다.
3. **받은 코드 중 하나를 골라 창을 닫고 30분 안에 다시 써본다.** 못 쓰면 이해한 것이
   아니다. 하루 한 개면 충분하다.
4. **PR 설명에 세 문장을 남긴다.** 무엇을 바꿨는가 / 왜 그렇게 했는가 / 다른 선택지는
   무엇이었는가. 회고와 면접 답변이 여기서 나온다.

## 면접 질문 목록

작업하면서 계속 채운다. 답하지 못하는 항목이 남아 있으면 그 부분은 아직 내 것이 아니다.

- [ ] 왜 Next.js가 아니라 Vite와 React인가
- [ ] 서버 상태와 클라이언트 상태의 경계를 어디에 그었고 왜 그렇게 나눴는가
- [ ] 차트 라이브러리를 무엇으로 골랐고 이유는 무엇인가
- [ ] 대시보드 초기 로딩에서 무엇이 병목이었고 어떻게 측정했는가
- [ ] 개선 전후 수치는 얼마인가
- [ ] 불필요한 리렌더를 어떻게 찾았고 어떻게 없앴는가
- [ ] 토큰을 어디에 저장했고 그 선택의 위험은 무엇인가

## 기록

- 개선 전후 수치는 **캡처와 함께** 남긴다. 나중에 복원할 수 없다.
- 회고는 작업이 끝난 뒤에 몰아 쓰지 않고 **PR을 올릴 때마다** 조금씩 쓴다.

## 이 규칙에서 파생된 결정

- **`react-perf` 룰 전부 off** ([eslint.config.js](../eslint.config.js))
  룰이 켜져 있으면 측정 없이 `memo`/`useCallback`을 붙이게 되고, 그렇게 붙은 코드는
  "왜 붙였나"에 "린트가 시켜서"밖에 답할 수 없다. 메모이제이션은 Profiler로 확인한 뒤
  수치와 함께 붙인다.
  - 남은 부채: 룰을 끄기 전에 이미 붙은 `memo` 5 / `useCallback` 28 / `useMemo` 5는
    측정 단계에서 근거를 재검토한다. 근거 없이 제거하는 것도 같은 잘못이다.
