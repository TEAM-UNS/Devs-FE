# 대시보드 필터 기억 실험 설계

> 대시보드 필터(전공·기업 규모·기간)를 들어올 때마다 기본값으로 둘지(A), 마지막 선택을 기억할지(B)
> 비교한다. 코드는 PR #179로 운영에 나가 있고, Amplitude 플래그 `dashboard-filter-memory`로 켠다.

---

## 1. 가설

마지막으로 고른 필터로 시작하면 다시 고르는 수고가 없어 대시보드에서 다음 화면(리포트·챗봇·기업 비교)으로
더 많이 넘어간다.

- 귀무가설: A와 B의 다음 화면 이동 비율이 같다
- 효과가 있다면 **저장된 값이 기본값과 다른 사람**(`wouldDiffer = true`)에게서만 나야 한다.
  저장값이 없거나 기본값과 같으면 B도 A와 같은 화면을 보기 때문이다

## 2. 무엇을 보는가

| 구분 | 지표                                                                                                       | 단위                  | 이벤트                                       |
| ---- | ---------------------------------------------------------------------------------------------------------- | --------------------- | -------------------------------------------- |
| 주   | 대시보드 방문 후 **같은 세션에서** `/weekly-report`·`/chat`·`/stack-compare`로 이동한 비율, `loggedIn`별로 | 방문(세션)            | `Dashboard Viewed` → `Page Viewed.page_path` |
| 보조 | 기본 필터를 바꾼 비율                                                                                      | 방문                  | `Dashboard Filter Changed`                   |
| 보조 | 많이 고른 값 (`filter`·`to` 분포)                                                                          | 변경 이벤트           | `Dashboard Filter Changed`                   |
| 관찰 | `wouldDiffer` 비율 — 기억이 실제로 화면을 바꿨을 방문의 비율                                               | 방문                  | `Dashboard Viewed.wouldDiffer`               |
| 감시 | 7일 재방문                                                                                                 | 기기 (아래 한계 참고) | `Dashboard Viewed`                           |

- 주 지표의 하위 그룹으로 `wouldDiffer = true`인 방문을 미리 정해 둔다. 이 값은 A 기간에도 계산되므로
  같은 조건끼리 비교할 수 있다
- 보조·관찰 지표는 판정에 쓰지 않는다. 결과를 해석하는 근거로만 쓴다

## 3. 기간과 배정

- **주 단위 A→B→A→B, 4주.** 사용자를 나누지 않고 그 주의 모든 사용자에게 같은 화면을 보여 준다.
  사용자가 적어 군을 나누면 양쪽 모두 표본이 너무 작아지고, 요일 효과는 주 단위로 상쇄된다
- 전환은 콘솔 롤아웃으로 한다. A주 = 롤아웃 0%, B주 = 롤아웃 100%
- 시작일·전환 요일·시각은 실험을 켤 때 정해 여기에 적는다

| 주차 | 기간 (KST) | 군  | 롤아웃 |
| ---- | ---------- | --- | ------ |
| 1    | 미정       | A   | 0%     |
| 2    | 미정       | B   | 100%   |
| 3    | 미정       | A   | 0%     |
| 4    | 미정       | B   | 100%   |

## 4. 데이터 처리 규칙

- **2026-11-02 23:30 KST(릴리스 #180) 이전 이벤트는 쓰지 않는다.** 그 전 버전이 남긴 `flagSource = timeout`,
  `(none)`, `flagLatencyMs`가 섞여 있다
- **군은 주차가 아니라 실제로 그린 화면(`filterMode`)으로 나눈다.** 플래그는 기다리지 않고 기기에 남은
  지난 값으로 정하므로, 전환 직후 첫 방문은 지난주 화면일 수 있다
  - `filterMode = default` → A, `remember` → B
  - `filterMode = fallback`(`flagSource = uncached`)은 비교에서 뺀다. 이 기기의 첫 방문이거나 광고 차단 등으로
    Amplitude가 막힌 경우라 A·B 어느 쪽 의도로도 배정되지 않았다. 대신 **몇 %였는지는 보고한다**
  - 민감도 분석으로 주차 기준(배정 의도대로) 결과도 같이 낸다. 두 결과의 방향이 다르면 그 사실을 적는다
- 팀원·테스트 기기는 뺀다. 기기 ID 목록은 실험 시작 때 적어 둔다

## 5. 기기 ID 한계 (결정: 방문 단위로 분석)

로그아웃(`useLogout` → `amplitude.reset()`)하면 기기 ID가 새로 생긴다. 또 로그인해도 `setUserId`를 부르지
않아 Amplitude에서는 모두 익명 기기로 센다.

- 주 지표는 **세션 안의 이동**이라 영향이 없다. 세션은 로그아웃 전후로 끊기지만 한 방문은 한 세션 안에 있다
- 7일 재방문은 기기 기준이라 **로그아웃한 사람은 재방문이 덜 잡힌다.** A·B 양쪽에 같은 방향으로 작용하므로
  비교는 가능하지만 절대값은 실제보다 낮다. 그래서 감시 지표로만 쓴다
- 같은 브라우저를 여러 사람이 쓰면 저장된 필터(`uns-dashboard-filters`)를 공유한다. 로그아웃해도 지우지 않는다

## 6. 필요 표본

기준 이동 비율 40%, 양측 α = 0.05, 검정력 80% 기준 검출 가능한 최소 차이.

| 군당 방문 수 | 검출 가능한 최소 차이 |
| ------------ | --------------------- |
| 30           | 35%p (40% → 75%)      |
| 100          | 19%p (40% → 59%)      |

지금 트래픽(하루 순 사용자 한 자릿수)으로는 4주 뒤 군당 수십 방문이 예상된다. **작은 차이는 원래 못 잡는
설계**이고, 결론을 내지 못하는 것도 정상 결과다.

## 7. 중단 기준

판정용이 아니라 사고를 막기 위한 기준이다. 아래 중 하나라도 보이면 롤아웃을 0%로 되돌리고 원인을 본다.

- B주에 대시보드 관련 에러가 늘어난다 (콘솔 에러·Sentry가 켜져 있다면 Sentry)
- B주에 `Dashboard Viewed` 대비 `Dashboard Filter Changed`가 A주보다 눈에 띄게 늘어난다 — 기억된 값을 다시
  되돌리느라 바꾸는 것일 수 있다. `to`가 기본값인 변경이 많은지 같이 본다
- `filterMode`와 롤아웃이 맞지 않는 방문(예: B주인데 `default`)이 전환 다음 날에도 절반을 넘는다 — 캐시가
  갱신되지 않는 버그일 수 있다

중간에 결과가 좋아 보인다고 일찍 끝내지 않는다. 4주를 채운다.

## 8. 결과 보고 형식

```
기간: YYYY-MM-DD ~ YYYY-MM-DD (A 2주, B 2주)
방문 수: A n, B n (fallback n, 전체의 x%)

주 지표 — 다음 화면 이동 비율
  전체         A x% vs B y%, 차이 +z%p (95% CI a ~ b)
  loggedIn     ...
  비로그인     ...
  wouldDiffer  ...
  주차 기준    ...

보조: 필터 변경 비율, 많이 고른 값
감시: 7일 재방문 (기기 기준, 로그아웃 사용자 과소 집계)

결론: 방향 + 신뢰구간. 구간이 0을 포함하면 "차이를 확인하지 못함"으로 적는다
```

- 차이의 방향과 95% 신뢰구간을 함께 적는다. p값만 적지 않는다
- 결론을 못 내면 못 냈다고 적는다. 표본이 작다는 이유로 방향만 보고 "효과 있음"이라 쓰지 않는다
